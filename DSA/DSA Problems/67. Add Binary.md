## 📌 Problem Statement

Given two binary strings `a` and `b`, return their sum as a binary string.

### Examples

**Example 1:**
- **Input:** `a = "11"`, `b = "1"`
- **Output:** `"100"`
- **Explanation:** $3 + 1 = 4$ in binary is `"100"`.

**Example 2:**
- **Input:** `a = "1010"`, `b = "1011"`
- **Output:** `"10101"`
- **Explanation:** $10 + 11 = 21$ in binary is `"10101"`.

### Constraints
- $1 \le a.\text{length}(), b.\text{length}() \le 10^4$
- `a` and `b` consist only of `'0'` or `'1'` characters.
- Each string does not contain leading zeros except for the zero itself.

---

## 💡 Solution 1: Baseline (`StringBuilder` Simulation)

### Code
```java
class Solution {
    public String addBinary(String a, String b) {
        int i = a.length() - 1;
        int j = b.length() - 1;
        int carry = 0;
        StringBuilder ans = new StringBuilder();

        while (i >= 0 || j >= 0 || carry != 0) {
            int bit1 = 0;
            int bit2 = 0;

            if (i >= 0) {
                bit1 = a.charAt(i) - '0';
            }
            if (j >= 0) {
                bit2 = b.charAt(j) - '0';
            }

            int sum = bit1 + bit2 + carry;
            int resultBit = sum % 2;
            carry = sum / 2;

            ans.append(resultBit);
            
            i--;
            j--;
        }
        return ans.reverse().toString();
    }
}
```

### How It Works:
1. Two pointers `i` and `j` traverse `a` and `b` backwards from the least significant bit (rightmost).
2. Missing bits (`i < 0` or `j < 0`) default to `0`.
3. Column sum = `bit1 + bit2 + carry`. Output bit is `sum % 2`, new carry is `sum / 2`.
4. Appends each bit to `ans`. Since bits were computed from right to left, `ans.reverse()` produces the final result.

## 🚀 Solution 2: Optimized Direct `char[]` Preallocation (Top 100% Runtime)

### Code
```java
class Solution {
    public String addBinary(String a, String b) {
        int i = a.length() - 1;
        int j = b.length() - 1;
        int c = 0; // carry

        // Max possible length of sum of two numbers of length L1, L2 is max(L1, L2) + 1
        char[] ans = new char[Math.max(a.length(), b.length()) + 1];
        int k = ans.length - 1; // write pointer starting from the end

        while (i >= 0 || j >= 0 || c != 0) {
            int s = c;
            if (i >= 0) {
                s += a.charAt(i) - '0';
                i--;
            }
            if (j >= 0) {
                s += b.charAt(j) - '0';
                j--;
            }

            ans[k] = (char) ((s % 2) + '0');
            c = s / 2;
            k--;
        }

        // If carry caused the array to fill completely to index 0 (k == -1)
        if (k == -1) {
            return String.valueOf(ans);
        }
        // Otherwise, skip the unused leading slot at index 0
        return String.valueOf(ans, k + 1, ans.length - k - 1);
    }
}
```

## 🔍 Deep-Dive: What's Improved & Why It's Faster?

```text
Solution 1 (StringBuilder):
[Loop] → ans.append() (Dynamic resizing check) → [Reversal Pass] ans.reverse() → [String Allocation] toString()
                                                    ↑ 2 passes over data

Solution 2 (Direct char[]):
[Preallocate char[MAX + 1]] → ans[k--] (Direct write backward) → [Single slice] String.valueOf(ans, offset, len)
                                                    ↑ 1 pass over data, zero resizing!
```

### 1. Eliminates the Reversal Pass (`O(N)` savings)
- **Solution 1:** Appends forward (`1`, `0`, `1`...) and must run a full second pass via `ans.reverse()` at the end.
- **Solution 2:** Fills `ans` **backwards from index `k = ans.length - 1`**, placing every character directly into its correct final position on the first pass.

### 2. Zero Array Resizing & Reallocations
- **Solution 1:** Default `StringBuilder()` starts with initial buffer capacity of 16. For strings with thousands of digits, it repeatedly reallocates and copies arrays as it grows ($16 \to 34 \to 70 \dots$).
- **Solution 2:** Precalculates the exact maximum required capacity upfront:
  $$\text{Capacity} = \max(\text{len}(a), \text{len}(b)) + 1$$
  *(Because adding two binary numbers can at most introduce 1 extra carry bit).*

### 3. Avoids Object Overhead & Method Dispatch
- **Solution 1:** Calls `ans.append()` method inside the hot loop, invoking internal checks and capacity validations.
- **Solution 2:** Directly writes to primitive `char[]` array in memory (`ans[k] = ...`), which JIT compilers aggressively vectorize.

### 4. Zero-Copy Leading Carry Handling
- If a final carry is generated, the full array is used (`k == -1`).
- If no final carry is generated, `String.valueOf(ans, k + 1, ans.length - k - 1)` creates a string starting from the true first digit without needing to shift elements or delete leading zeros.

## 📊 Complexity & Performance Comparison

| Metric | Solution 1 (`StringBuilder`) | Solution 2 (`char[]` Preallocation) |
| :--- | :--- | :--- |
| **Time Complexity** | $O(\max(N, M))$ (2 passes) | **$O(\max(N, M))$ (Single pass, ~2x faster)** |
| **Space Complexity** | $O(\max(N, M))$ | **$O(\max(N, M))$ (Zero reallocation overhead)** |
| **Passes over output** | 2 passes (Append + Reverse) | **1 pass (Direct backward fill)** |
| **Heap Allocations** | Multiple dynamic resizing arrays + Builder | **Single exact `char[]` buffer** |
| **LeetCode Runtime** | ~2 ms (Top 60-70%) | **0-1 ms (Top 100%)** |

## 💡 Key Takeaways & Interview Wisdom

1. **Always calculate maximum output bounds:** The sum of two numbers of length $N$ and $M$ will always have at most $\max(N, M) + 1$ digits.
2. **Backward indexing eliminates reverse passes:** When computing results right-to-left, writing directly into a preallocated array from `arr.length - 1` downwards saves a full traversal.
3. **`String.valueOf(char[], offset, count)`** is the cleanest, zero-overhead way to construct a String from a partially filled char buffer.
